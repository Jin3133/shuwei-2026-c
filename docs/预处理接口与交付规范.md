# 2026 数维杯 C 题：预处理接口与交付规范

> 版本：v1.0  
> 日期：2026-11-20  
> 用途：统一EgoDemo、EgoPro、EgoStandard的读取、输出、合并和验收标准  
> 关联文档：`C题数据集与预处理规范.md`

---

## 1. 目的

本文档解决三个人并行处理数据时的以下问题：

- 三套原始数据列名不同；
- 时间戳和质量标记来源不同；
- 缺失值、布尔值和枚举值写法不一致；
- 同一字段在不同代码中含义不同；
- 交付时只给结果表，没有审计记录和运行说明；
- 合并时发现数据类型、单位或主键不一致。

所有数据读取程序必须按本文档输出。不允许通过临时口头说明替代字段和交付规范。

---

## 2. 适用范围

本规范适用于：

```text
EgoDemo 31条记录
EgoPro 14条记录
EgoStandard 24条记录
```

需要统一交付的主产物：

```text
records.csv
frames.parquet
segments.csv
audit.csv
run_info.json
```

合并完成后再生成：

```text
q1_windows.parquet
q2_masks.parquet
q3/public/
q3/train/
q3/private/
```

## 3. 通用命名和类型约定

### 3.1 字段命名

- 全部使用小写英文和下划线；
- 不使用空格、中文列名和大小写混合；
- 布尔字段使用 `_flag`、`_ok` 或 `is_` 表示；
- 比例使用 `_ratio`；
- 秒使用 `_s`；
- 纳秒使用 `_ns`；
- 毫秒使用 `_ms`；
- 计数使用 `n_` 或 `_count`。

### 3.2 单位

| 数量 | 统一单位 |
|---|---|
| 相对时间 | 秒 |
| 原始绝对时间 | 保留原始格式，另列存储 |
| 3D位置 | 米 |
| 速度 | 米/秒 |
| 旋转 | 四元数原始顺序另行记录，不在未验证时强制转换 |

不得根据猜测自动将坐标乘1000或除1000。单位必须来自元数据、字段说明或经记录的几何尺度核对。

### 3.3 缺失值

统一使用真正的缺失值：

```text
Parquet: null
CSV: 空字段
Python: None / NaN
```

禁止使用以下数值代表缺失：

```text
0
-1
999
[0, 0, 0]
```

### 3.4 布尔值

写出时只能是：

```text
true
false
null
```

其中：

- `true`：明确为真；
- `false`：存在对应记录，且明确为假；
- `null`：信息不存在或无法判断。

不得将 `null` 默认转成 `false`。

### 3.5 枚举值

统一使用小写下划线：

```text
split: train / validation / test
quality: good / bad / missing
bad_reason: occlusion / near_edge / other
alignment_type: exact / nearest / unmatched
dataset: EgoDemo / EgoPro / EgoStandard
```

`dataset` 保留官方大小写，其余枚举统一小写。

## 4. 读取器接口

### 4.1 入口函数

三套数据分别实现：

```python
load_egodemo(record_path, official_record) -> RecordBundle
load_egopro(record_path, official_record) -> RecordBundle
load_egostandard(record_path, official_record) -> RecordBundle
```

### 4.2 `official_record`

来自官方 `record_split.csv` 的一行，至少包含：

```text
episode_uuid
dataset
environment_id
scene_id
operator_id
split
```

### 4.3 `RecordBundle`

每个读取器返回相同结构：

```python
RecordBundle(
    record: dict,
    left_hand: table,
    right_hand: table,
    quality: table,
    segments: table,
    issues: list[dict],
)
```

字段要求：

| 成员 | 内容 |
|---|---|
| `record` | 记录级元数据，必须包含 `episode_uuid`、`dataset`、`sample`和`split` |
| `left_hand` | 左手原始时间戳、21点3D位置和源定位 |
| `right_hand` | 右手原始时间戳、21点3D位置和源定位 |
| `quality` | 原始质量时间、手别、标记和原因 |
| `segments` | 语义区间的开始、结束、描述和原始索引 |
| `issues` | 读取期间发现的缺失、冲突和不确定问题 |

读取器只负责读取和格式转换，不在读取器内进行：

- 插值；
- 平滑；
- 速度计算；
- 人工mask；
- 数据标准化；
- 删除坏帧。

## 5. `records.csv` 接口

一条采集记录一行。

### 5.1 必需字段

| 字段 | 类型 | 允许缺失 | 定义 |
|---|---|---:|---|
| `episode_uuid` | string | 否 | 原始记录内部主键 |
| `dataset` | string | 否 | EgoDemo/EgoPro/EgoStandard |
| `sample` | string | 否 | 原始记录目录名 |
| `source_path` | string | 否 | 相对数据根目录的路径 |
| `environment_id` | string | 否 | 官方环境标识 |
| `scene_id` | string | 是 | 官方场景标识 |
| `operator_id` | string | 是 | 官方操作者标识 |
| `split` | string | 否 | train/validation/test |
| `n_frames` | int64 | 否 | 统一帧级表行数 |
| `duration_s` | float64 | 否 | 主时间轴末值减首值 |
| `actual_fps` | float64 | 是 | `1/median(diff(timestamp_s))` |
| `n_segments` | int64 | 否 | 区间数 |
| `left_bad_ratio` | float64 | 是 | 左手官方坏质量时间戳比例 |
| `right_bad_ratio` | float64 | 是 | 右手官方坏质量时间戳比例 |
| `duplicate_timestamp_count` | int64 | 否 | 重复时间戳数 |
| `nonmonotonic_count` | int64 | 否 | 非单调时间戳数 |
| `large_gap_count` | int64 | 否 | 大时间间隔数 |
| `duplicate_status` | string | 否 | unique/duplicate_uuid/metadata_conflict |
| `usable` | bool | 否 | 是否至少可用于一项建模任务 |
| `exclusion_reason` | string | 是 | 排除或限制使用原因 |

### 5.2 主键

```text
episode_uuid
```

要求：

- 每个 `episode_uuid` 只出现一次；
- 必须能在官方 `record_split.csv` 找到；
- `dataset`、`environment_id`、`split` 必须与官方索引一致；
- `sample` 只是目录定位字段，不取代 `episode_uuid`。

## 6. `frames.parquet` 接口

一行表示一条记录在一个统一时间戳上的左右手状态、质量和语义区间。

### 6.1 唯一键

```text
frame_id
```

`frame_id` 格式：

```text
{episode_uuid}_{frame_number:06d}
```

例如：

```text
1e3b4ce1-a1d2-4f23-9c21-448a039474b7_000025
```

`frame_number` 是统一时间轴行号，不强制等于原始 `frame_index`。

### 6.2 必需字段

| 字段 | 类型 | 允许缺失 | 定义 |
|---|---|---:|---|
| `frame_id` | string | 否 | 帧级唯一标识 |
| `episode_uuid` | string | 否 | 所属记录 |
| `dataset` | string | 否 | 数据源 |
| `sample` | string | 否 | 原始目录名 |
| `split` | string | 否 | 官方划分 |
| `timestamp_s` | float64 | 否 | 记录内公共起点开始的相对秒数 |
| `timestamp_raw` | string | 是 | 原始时间戳或可逆定位表示 |
| `source_frame_index` | int64 | 是 | 原始帧或消息索引 |
| `source_locator` | string | 否 | 原始文件与行/帧定位 |
| `left_palm_x/y/z` | float32 | 是 | 左掌心原始坐标，单位米 |
| `right_palm_x/y/z` | float32 | 是 | 右掌心原始坐标，单位米 |
| `left_raw_quality_flag` | bool | 是 | 原始数据是否明确标记左手质量问题 |
| `right_raw_quality_flag` | bool | 是 | 原始数据是否明确标记右手质量问题 |
| `left_bad_reasons` | list<string> | 是 | 标准化左手质量原因 |
| `right_bad_reasons` | list<string> | 是 | 标准化右手质量原因 |
| `left_quality` | string | 否 | good/bad/missing |
| `right_quality` | string | 否 | good/bad/missing |
| `left_fit_ok` | bool | 否 | 是否可进入左手指定模型拟合 |
| `right_fit_ok` | bool | 否 | 是否可进入右手指定模型拟合 |
| `left_ref_ok` | bool | 否 | 左手是否可作为人工mask误差参考 |
| `right_ref_ok` | bool | 否 | 右手是否可作为人工mask误差参考 |
| `segment_id` | string | 是 | 当前时刻覆盖的官方语义区间ID |
| `continuity_block_id` | string | 否 | 物理时间连续块 |

### 6.3 掌心定义

左右手使用相同索引：

```text
0: Wrist
5: Index MCP
9: Middle MCP
13: Ring MCP
17: Little MCP
```

\[
p_t^{\mathrm{palm}}=
\frac{p_{0,t}+p_{5,t}+p_{9,t}+p_{13,t}+p_{17,t}}{5}.
\]

计算要求：

- 5个点必须全部存在；
- 坐标必须全部有限；
- 任一条件失败时，对应掌心三列全部为缺失；
- 不允许自动改用剩余点平均；
- 不允许用0、上一帧或插值代替。

### 6.4 时间定义

| 数据源 | `timestamp_s` 首选来源 |
|---|---|
| EgoDemo | Parquet `timestamp` |
| EgoPro | `_offset_from_first_log_s` |
| EgoStandard | `_offset_from_first_log_s` |

要求：

- 单位为秒；
- 同一 `episode_uuid` 内按 `timestamp_s` 升序；
- 重复时间戳不静默覆盖；
- 如左右手相对时间不共享起点，必须转换到共同记录起点后再对齐；
- 禁止将绝对纳秒时间先转为float秒再相减。

### 6.5 质量标记定义

`left_raw_quality_flag` 和 `right_raw_quality_flag` 为可空布尔值：

| 值 | 含义 |
|---|---|
| `true` | 原始数据明确标记对应手存在质量问题 |
| `false` | 原始质量记录存在，且未标记该手问题 |
| `null` | 无对应质量记录或无法判定 |

原因标准化：

| 原始值 | 对应手 | 统一值 |
|---|---|---|
| `occlusion` | 由原字段决定 | `occlusion` |
| `left:occlusion` | left | `occlusion` |
| `right:occlusion` | right | `occlusion` |
| `near edge` | 由原字段决定 | `near_edge` |
| `left:near edge` | left | `near_edge` |
| `right:near edge` | right | `near_edge` |
| 其他未知值 | 由原字段决定 | `other` |

`left_bad_reasons` 和 `right_bad_reasons` 的空值含义：

| 值 | 含义 |
|---|---|
| `[]` | 质量记录存在，对应手无问题 |
| `['occlusion']` | 明确遮挡 |
| `['occlusion','near_edge']` | 同时存在多个原因 |
| `null` | 质量未知 |

如整行 `is_bad=true`，但原因只指向右手，不得将左手也设为 `true`。

### 6.6 统一质量和用途字段

| 字段 | 含义 |
|---|---|
| `quality` | good/bad/missing三值统一质量 |
| `fit_ok` | 是否可进入当前指定模型拟合 |
| `ref_ok` | 是否可作为人工mask误差参考 |

默认规则：

```text
missing -> fit_ok=false, ref_ok=false
bad     -> 可用于质量分类拟合，但ref_ok=false
good    -> 满足窗口连续性时可fit_ok=true, ref_ok=true
```

`fit_ok` 不是所有模型共用的绝对标签。如状态预测模型和质量分类模型条件不同，可在样本索引中另行生成具体拟合资格，但不修改原始质量字段。

### 6.7 `segment_id`

优先使用 `source_segment_index.csv` 的官方 `unit_id`，例如：

```text
U_1048a185fab3
```

区间赋值：

\[
start_s\le timestamp_s<end_s.
\]

| 情况 | 处理 |
|---|---|
| 命中一个区间 | 赋官方 `unit_id` |
| 未命中任何区间 | `null` |
| 命中多个区间 | `segment_id=null`，同时写入问题表，不自行选择 |
| 刚好在相邻区间分界点 | 按半开区间进入后一区间 |

如原始标注尚未关联到官方索引，可临时使用：

```text
{episode_uuid}_S{source_segment_index:03d}
```

但正式交付前必须尽可能替换为官方 `unit_id`，无法关联的区间必须列入 `audit.csv`。

## 7. `segments.csv` 接口

每个原始语义区间一行。

### 7.1 必需字段

| 字段 | 类型 | 允许缺失 | 定义 |
|---|---|---:|---|
| `segment_id` | string | 否 | 官方 `unit_id` 或可追溯临时ID |
| `episode_uuid` | string | 否 | 所属记录 |
| `dataset` | string | 否 | 数据源 |
| `sample` | string | 否 | 原始目录名 |
| `split` | string | 否 | 官方划分 |
| `source_segment_index` | int64 | 是 | 原记录内区间索引 |
| `family_id` | string | 是 | P/A/L，来自官方源区间索引 |
| `start_s` | float64 | 否 | 记录内开始秒数 |
| `end_s` | float64 | 否 | 记录内结束秒数 |
| `duration_s` | float64 | 否 | `end_s-start_s` |
| `description` | string | 是 | 原始语义描述，仅离线审计 |
| `eligible` | bool | 是 | 官方是否进入第三问采样池 |
| `n_frames` | int64 | 否 | 半开区间内帧数 |
| `good_ratio` | float64 | 是 | 区间内手部可用比例 |
| `bad_ratio` | float64 | 是 | 区间内明确质量问题比例 |
| `mapping_status` | string | 否 | matched/unmatched/ambiguous |

### 7.2 唯一键

```text
segment_id
```

### 7.3 边界规则

- 区间必须满足 `end_s > start_s`；
- `duration_s` 必须与 `end_s-start_s` 在浮点容差内一致；
- 所有区间使用 `[start_s,end_s)`；
- 超出记录时间范围的区间不自动截断，先记录问题；
- `description` 不得进入第三问在线策略输入。

## 8. `audit.csv` 接口

所有不能静默处理的问题一律写入 `audit.csv`。

### 8.1 必需字段

| 字段 | 类型 | 定义 |
|---|---|---|
| `issue_id` | string | 问题唯一ID |
| `severity` | string | warning/error |
| `dataset` | string | 数据源 |
| `episode_uuid` | string | 相关记录，可空 |
| `source_locator` | string | 原始文件和行/帧定位 |
| `issue_type` | string | 问题类型 |
| `message` | string | 简明问题描述 |
| `action` | string | kept/excluded/deduplicated/unresolved |
| `affected_output` | string | records/frames/segments/q1/q2/q3 |

### 8.2 标准问题类型

```text
missing_uuid
uuid_not_in_official_split
metadata_conflict
duplicate_timestamp
nonmonotonic_timestamp
large_time_gap
invalid_keypoint_count
nonfinite_position
quality_unmatched
segment_unmatched
segment_overlap
segment_out_of_range
unknown_quality_reason
```

`severity=error` 的问题必须在正式合并前解决，或明确将对应数据标记为不可用。

## 9. `run_info.json` 接口

每次交付必须附带：

```json
{
  "dataset": "EgoDemo",
  "created_at": "2026-11-20T12:00:00+08:00",
  "code_version": "git commit or manual version",
  "source_root": "relative or configured path",
  "official_split_hash": "sha256",
  "source_segment_index_hash": "sha256",
  "record_count_expected": 31,
  "record_count_output": 31,
  "frame_count_output": 0,
  "segment_count_output": 0,
  "error_count": 0,
  "warning_count": 0,
  "command": "python ...",
  "notes": []
}
```

要求：

- `created_at` 使用带时区的ISO 8601时间；
- 不得只写“最新版”或“最终版”；
- 代码没有git提交时，至少填手工版本号；
- 运行命令必须可复制执行；
- 不在文件中写入密码和不必要的个人信息。

## 10. 交付目录规范

每个数据源使用一个独立交付目录：

```text
deliveries/
├── egodemo/
│   ├── records.csv
│   ├── frames.parquet
│   ├── segments.csv
│   ├── audit.csv
│   ├── run_info.json
│   └── src/
├── egopro/
│   └── ...
└── egostandard/
    └── ...
```

`src/` 中必须包含：

- 可重新生成本次交付的代码；
- 配置或明确的命令行参数；
- 不得只交付Notebook中已丢失上下文的零散单元格；
- 不得在代码中写死只对本人电脑有效的绝对路径。

正式合并后输出：

```text
data_processed/
├── records.csv
├── frames.parquet
├── segments.csv
├── field_dictionary.csv
├── audit.csv
└── preprocessing_run.json
```

## 11. 合并规范

合并程序不负责“猜测”各人交付的字段含义。合并前所有交付必须通过本地验证。

### 11.1 合并顺序

```text
1. 检查目录和必需文件
2. 检查列名
3. 检查数据类型
4. 检查枚举值
5. 检查主键和外键
6. 检查单位和时间范围
7. 检查数据源内统计量
8. 纵向合并
9. 检查官方总数
10. 生成总运行记录
```

### 11.2 禁止的合并行为

- 列缺失时自动补默认值；
- 时间戳重复时只保留最后一行；
- 将空质量标记自动当作质量良好；
- 将空掌心坐标填成零；
- 将 `val` 静默改为 `validation` 而不报告上游错误；
- 按目录名去重而不使用 `episode_uuid`；
- 因少量坏帧删除整条记录。

## 12. 自动验收规范

### 12.1 文件级检查

- [ ] 5个必需文件全部存在；
- [ ] 文件能正常读取；
- [ ] Parquet schema与本文档一致；
- [ ] CSV使用UTF-8或UTF-8 with BOM；
- [ ] `run_info.json` 为有效JSON；
- [ ] `src/` 中有可执行代码。

### 12.2 `records.csv` 检查

- [ ] `episode_uuid` 不为空且唯一；
- [ ] 记录数与交付数据源一致；
- [ ] `dataset` 为期望数据源；
- [ ] `split` 只包含train/validation/test；
- [ ] 每条记录都能与官方split关联；
- [ ] `n_frames`、`n_segments` 为非负整数；
- [ ] `duration_s` 为正数；
- [ ] 各ratio位于0至1或为空。

### 12.3 `frames.parquet` 检查

- [ ] `frame_id` 唯一；
- [ ] `episode_uuid` 都能在 `records.csv` 中找到；
- [ ] `timestamp_s` 有限且非负；
- [ ] 同一 `episode_uuid` 内时间递增；
- [ ] 掌心三列同时有值或同时缺失；
- [ ] 掌心数值有限；
- [ ] 布尔字段只包含true/false/null；
- [ ] 质量枚举只包含good/bad/missing；
- [ ] 质量原因只包含occlusion/near_edge/other；
- [ ] `segment_id` 为空或能在 `segments.csv` 中找到；
- [ ] `source_locator` 不为空。

### 12.4 `segments.csv` 检查

- [ ] `segment_id` 唯一；
- [ ] `episode_uuid` 都能在 `records.csv` 中找到；
- [ ] `end_s > start_s`；
- [ ] `duration_s` 与 `end_s-start_s` 一致；
- [ ] `family_id` 为P/A/L或空；

## 14. 合并后的三问接口

### 14.1 Q1窗口接口

```text
episode_uuid
hand
split
history_start_s
history_end_s

continuity_block_id

```

默认主模型输入：

\[
X_t=[\Delta p_t,v_t,h,q_t].
\]

`dataset` 不进入默认主模型，只用于分层报告和消融实验。

预测目标：

\[
X_{t-L+1:t}\rightarrow
\{p_{t+h}-p_t\}_{h=1}^{H}.
\]

### 14.2 Q2 mask接口

```text
mask_id
episode_uuid
hand
split
segment_id
mask_start_s
mask_end_s
mask_duration_s
observation_budget
request_cost
return_delay_s

```

mask只从 `ref_ok=true` 的连续区间生成。mask后必须同时隐藏位置和所有依赖该位置的派生特征。

### 14.3 Q3在线接口

策略只能调用：

```python
get_visible(job_id, trial_state)
```

前缀层级由回放器根据释放状态、付费查看次数和返回延迟决定，策略不得自行传入可见秒数。

```text
q3/public/   策略可读
q3/train/    训练流程可读的训练标签和前缀
q3/private/  仅回放器和评分器可读
```

`q3/private/` 中的源ID、区间边界、真实时长和作业分配不得出现在策略输入中。
